# Chute Architecture Map

Audit pass 1, taken on branch `claude/chute-architecture-audit-1c0svk` at 2026-09-24. The purpose is the coming refactor of the Chute brains: how the HomeRoom's main Chute and the per-row Drop ingest files, route them to an account, analyze them, and fan the resulting intelligence out across the surfaces that read it. The map is biased toward the ingest path and everything downstream of a filing.

Method: nine readers mapped the repo by responsibility, nine cite-checkers refuted each map line by line against the files, two synthesis agents wrote the trace and the rankings, twenty skeptics attacked the refactor candidates, and a critic hunted for gaps. The ingest core was read by hand as well, and the thirteen test suites that pin it were run. Every cite below survived a line check. Claims that come from code shape rather than a run are marked [inferred].

Status after pass 1: the bug pass that followed this map landed on main as PR #329 (squash d126259, 2026-09-24). It fixed the stale guard comments and receipt copy (§4), the "cross it out" advice (§4), the partial undo (§4, now takes back everything a filing wrote), the vault double-write (§4, candidate 6), and the verify-chain gap (the test script now runs 41 suites). Bug 5's premise did not reproduce; the receipt now names the model's judgment on a rules-filed paste. The Chute picker's mismatch fall-through and the Drop's first-file-only loop are reproduced in tests/ingest-defects-deferred.test.ts and wait for the refactor. Line numbers cited below are as of 8fa2803, before that PR. The bug pass has its own record at docs/architecture/chute-ingest-defects.md. Audit pass 2, the derived-fact ledger that designs candidate 2, is at docs/architecture/derived-fact-ledger.md.

## 1. Entry points and routes

- **Every page is a self-gating server component.** 20 of 25 pages and all 7 route handlers declare force-dynamic: src/app/room/page.tsx:81, src/app/accounts/page.tsx:41, src/app/groundwork/page.tsx:93, src/app/intranet/page.tsx:40, src/app/playbook/page.tsx:17. So revalidatePath only busts the router cache. Nothing is statically cached anywhere.
- **/room is the HomeRoom.** The wayfinder labels it so at src/components/app-wayfinder.tsx:37-43 and files /today, /, /pipeline and /intake under archived surfaces at :86-122. Contradiction: /today still runs its full derivation at src/app/today/page.tsx:606-640 and every filing revalidates it at src/app/room/actions.ts:68.
- **The Chute mounts on exactly two pages.** /room hands it routingRoster() at src/app/room/page.tsx:793 and :842. /intranet hands it an inline roster with emails and domains only at src/app/intranet/page.tsx:121-138. The per-row Drop exists only inside RoomClient at src/app/room/room-client.tsx:532-545 and :1837. ActivityDock on /intranet is a third drop zone for the .csv alone at src/app/activity/dock.tsx:46-100.
- **The route handlers exist because server actions block navigation.** POST /intranet/run and /intranet/read wrap runBrain and readCapture at src/app/intranet/run/route.ts:15-18 and read/route.ts:12-16. GET /activity/evidence is the one door for staged bodies at src/app/activity/evidence/route.ts:1-12.
- **Middleware guards two paths by cookie presence.** src/proxy.ts:4-11 delegates to src/lib/access-proxy.ts:20-33, which redirects only "/" and "/prospect-field". Every other page calls getAppAccess at src/lib/auth.ts:130-186 itself.
- **room/actions.ts is the filing spine.** Imported by chute.tsx, room-client.tsx, today/actions.ts:21 and groundwork/actions.ts:15. Its refresh() at :65-71 revalidates /room, /accounts, /today, /groundwork and /, and never /intranet, /playbook or /sendbook.

Weight: src/app/room/page.tsx (the HomeRoom loader and the only mount of RoomClient), src/app/room/actions.ts (the spine), src/app/room/chute.tsx, src/app/room/room-client.tsx (the Drop lives inside the largest client file in the app), src/app/intranet/page.tsx (the second Chute mount with its own roster).

- **The fingerprint contradicts its own comment.** pasteFingerprint at paste-files.ts:42-53 hashes the whole normalized paste including the head line. ### Do the Chute and the Drop share a code path?

They share the server entirely and fork on the client. Shared: readFileToText, roomPaste, roomPasteUndo, githubArchiveGrant and archiveFileToGitHub. Forked:

- Routing runs only in the Chute at chute.tsx:361-376. The Drop is pre-bound to row.accountId at room-client.tsx:488-490 and its only routing check is judgeFiling inside roomPaste.
- Files per drop. The Chute fires one un-awaited swallow per file under one batch id at chute.tsx:383-387. The Drop reads the FIRST readable file and vaults every other file unread at room-client.tsx:581-600. Two .eml files dropped on a row file one and vault the other. The Chute files both.
- The .csv probe and the second-record drive loop exist only in the Chute at chute.tsx:286-343.
- The vault grant is memoized per session in the Chute at chute.tsx:243-256 and fetched fresh per call in the Drop at room-client.tsx:556-560.
- Unreadable files. The Chute routes them by filename and vaults with no guard at chute.tsx:357-365. The Drop archives `unreadable` at once at :596-597, then passes the whole `files` list as `waiting` at :598, and filePaste archives `waiting` again on accept at :498-500, as does readDroppedFile on a failed read at :538-540. Every non-primary file is PUT twice; archive.ts:117-128 folds a timestamp on collision, so two copies land.
- Vault timing on readable files is the same at both doors, after roomPaste returns ok, at chute.tsx:219 and room-client.tsx:498-500. The Drop's "vault waits on the guard" comment at :591-599 fails on its own busy branch: a readable file dropped while pending or reading is archived unguarded at :599.
- Mismatch resolution. The Chute collapses "no sure match" and "guard objected" into one picker whose every choice files with force=true at chute.tsx:555-579 and :586-600, so nothing is re-judged. The Drop holds text and files in a two-sided banner whose force button re-runs the whole read against the same row at room-client.tsx:1974-2013.
- Chute picker fall-through [from code shape, not exercised]: fileTo patches a mismatch without text at chute.tsx:233-234, and text is patched only on the pick branch at :376. The select's `if (a && it.text)` at :591 therefore fails on an auto-routed file the guard rejected and falls to vaultTo at :600, so the readable text is vaulted under the picked account and never re-filed.
- Receipts. The Chute persists noteIds to localStorage per Chicago day at chute.tsx:76-135, so undo survives a reload. The Drop keeps them in component state at room-client.tsx:516-519. The Chute has a "dupe" state at :231-232; the Drop shows r.reason as a generic note at :527. Only the Chute has the batch-mate suggestion at :389-403.
- Race [inferred]: concurrent Chute swallows each pass the findUnique guard at actions.ts:204-208 before any of them stamps at :454. The Drop serializes on pending or reading.

Copy that contradicts the code: room-client.tsx:511-514 says "the account check did not run" on readFailed, but the early guard ran keyless and the late guard runs with an empty claim at actions.ts:233-254 and :310-317. room-client.tsx:513 says "cross it out and drop it again", but cross-out writes a hide:note: disposition at :1417 and leaves the pastehash, so the re-drop returns "Already on file" at :202-226. chute.tsx:6-7 says the guard runs "when the key is on", but the early rung is rules-only.

Weight: src/app/room/actions.ts (every ingest verb and every fan-out write, about 40 imports), src/app/room/chute.tsx, src/app/room/room-client.tsx, src/lib/intel/misfile.ts (the one guard, twice per filing), src/lib/route-capture.ts (the pure router at two layers).
